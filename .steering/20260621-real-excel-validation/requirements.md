# 実 Excel 検証 要求定義

## 1. 目的

TapInShift v1 のローカルエージェントが、実際のパスワード付き Excel 勤務表に対して安全に出勤、退勤、手動編集を反映できることを確認する。

devcontainer 上では Excel アプリを使った xlwings 実書き込みを保証できないため、Windows または macOS の Excel 実機で検証できる状態を整える。

## 2. 対象範囲

- `config/config.local.json` に実勤務表向け設定を作成する手順を明確にする。
- 実勤務表の対象シート、対象行、対象列に合わせて反映できることを確認する。
- `tapinshift-agent --check-config` でローカル設定と環境変数の不足を確認できることを確認する。
- Slack App Home からの出勤、退勤、日付編集が Excel へ反映されることを確認する。
- Slack App Home から丸め単位を選択し、以降の出勤・退勤へ適用できることを確認する。
- Excel 反映失敗時に SQLite へ失敗状態とエラー内容が保存されることを確認する。
- 実勤務表へ直接書き込む前に、検証用コピーまたは復元可能なバックアップを用意する。

## 3. 対象外

- Excel 勤務表フォーマット自体の変更。
- クラウドキュー、公開 API、Web サーバーの追加。
- Slack App の本番配布、複数ユーザー対応。
- 実勤務表ファイル、SQLite、token、API key、Excel パスワードの Git 管理。

## 4. 前提

- 実勤務表はローカルの Git 管理対象外パスに配置する。
- 検証時は原本ではなく検証用コピーを使う。原本で確認する必要がある場合も、事前に復元可能なバックアップを作成する。
- Excel パスワードは `TAPINSHIFT_EXCEL_PASSWORD` などの環境変数で渡す。
- Slack token と OpenAI API key は環境変数で渡す。
- OpenAI API key が未設定の場合はローカルルール分類へフォールバックする。
- 実 Excel 書き込み確認は Excel アプリが入った Windows または macOS で行う。

## 5. 実勤務表マッピング

| 項目 | 値 |
| --- | --- |
| シート名 | `6` |
| データ行 | `7..37` |
| 日付列 | `L` |
| 出勤列 | `F` |
| 退勤列 | `G` |
| 届出内容列 | `W` |
| 経費内容列 | `Y` |
| 金額列 | `AB` |
| 既定値 | `B=1`, `C=1`, `D=0`, `E=0` |

## 6. ユーザーストーリー

### 6.1 出勤反映

ユーザーとして、Slack App Home の出勤ボタンを押すことで、当日の出勤時刻を実勤務表の対象行へ反映したい。

### 6.2 退勤反映

ユーザーとして、Slack App Home の退勤ボタンを押すことで、当日の退勤時刻を実勤務表の対象行へ反映したい。

### 6.3 メモ付き反映

ユーザーとして、勤務した拠点や交通費の経路・金額などの任意メモを入力し、分類できる内容だけを勤務表の届出・経費欄へ反映したい。

### 6.4 手動編集

ユーザーとして、Slack App Home の日付選択から対象日を開き、出勤、退勤、届出、経費内容、金額を上書き修正したい。

### 6.5 失敗時確認

ユーザーとして、Excel 反映に失敗した場合でも、入力内容とエラーを SQLite に残して後から復旧判断したい。

### 6.6 丸め単位変更

ユーザーとして、Slack App Home から丸めなし、5分、10分、15分、20分、30分のいずれかを選び、以降の出勤・退勤時刻に適用したい。

## 7. 受け入れ条件

- `config/config.local.json` に実勤務表向け設定を作成できる。
- `tapinshift-agent --config config/config.local.json --check-config` で設定状態を確認できる。
- 検証対象の Excel ファイルが原本ではなく検証用コピー、または復元可能なバックアップ作成済みのファイルである。
- 出勤操作で対象日の `F` 列に時刻が反映される。
- 退勤操作で対象日の `G` 列に時刻が反映される。
- 丸め単位を選択すると SQLite に保存され、以降の打刻に反映される。
- 打刻時、対象セルに既存値がある場合は上書きせず失敗として保存される。
- 手動編集では対象日の `F`, `G`, `W`, `Y`, `AB` を上書きでき、空欄項目は既存値を保持する。
- 対象行が見つからない場合は失敗として保存され、Excel を壊さない。
- 秘密情報と実勤務表ファイルは Git 管理対象に含まれない。

## 8. 制約

- 実 Excel 検証は devcontainer の自動テスト対象外とする。
- 原本の実勤務表へいきなり書き込まない。
- 実勤務表のパスワードをファイル、ログ、ドキュメントへ記録しない。
- 実勤務表ファイルをコミットしない。
- 既存の勤務表セルを打刻で上書きしない。
- 手動編集のみ上書きを許可する。
