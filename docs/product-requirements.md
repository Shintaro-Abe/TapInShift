# TapInShift プロダクト要求定義書

## 1. プロダクト概要

TapInShift は、Slack の App Home から出勤・退勤を記録し、ローカル Excel 勤務表へ反映する勤怠入力ツールである。

クラウドキュー同期では、AWS Lambda Function URL と DynamoDB が Slack 操作を受け付け、Windows Agent が起動後に未同期イベントを Excel へ反映する。Excel ファイルと Excel password はクラウドに保存しない。

## 2. プロダクトビジョンと目的

### ビジョン

勤務表入力を Slack の日常導線に統合し、Excel 勤務表への転記作業を最小化する。

### 目的

- 出勤・退勤時刻を Slack から即時記録できるようにする。
- 任意メモから届出内容、経費内容、金額を抽出し、勤務表に反映する。
- Excel 反映に失敗した場合でも、SQLite に監査ログを残して後から確認できるようにする。
- パスワード付きローカル Excel 勤務表を既存運用のまま利用する。
- Windows 端末停止中でも Slack 操作を受け付け、起動後に同期できるようにする。

## 3. ターゲットユーザー

- 個人または小規模運用で、勤務表を Excel で提出しているユーザー。
- Slack を日常的に開いており、勤務開始・終了時に Slack から記録したいユーザー。
- 自宅 PC またはローカル端末上で勤務表ファイルを管理しているユーザー。

## 4. ユーザー課題・ニーズ

### 課題

- 出勤・退勤時刻を後から Excel に手入力すると、入力忘れや時刻の記憶違いが起きやすい。
- 経費や届出内容を別途メモしてから勤務表へ転記する手間がある。
- パスワード付き Excel 勤務表を扱うため、一般的なクラウド勤怠ツールへ移行しにくい。
- 自動反映に失敗したとき、何が記録済みで何が未反映か追跡しづらい。
- Windows 端末をシャットダウンしている外出中は、従来のローカル常駐方式ではSlack操作を処理できない。

### ニーズ

- Slack App Home で出勤・退勤を少ない操作で記録したい。
- 任意メモを入力した場合、経費や届出の候補を自動分類してほしい。
- Excel への反映結果を Slack 上で確認したい。
- 失敗時にもローカルに履歴を残し、手動で復旧できる状態にしたい。
- 外出中でもSlackで出勤・退勤・メモ・編集を受け付け、後でExcelへ同期したい。

## 5. 主要機能

### 5.1 Slack App Home 打刻

- Slack App Home に任意メモ入力欄を表示する。
- 出勤ボタンを押すと出勤時刻を記録する。
- 退勤ボタンを押すと退勤時刻を記録する。
- 丸め単位を選択するとクラウド設定に保存し、以降の出勤・退勤に適用する。
- 処理結果を App Home に状態メッセージとして表示する。

### 5.2 任意メモ分類

- 出勤・退勤ボタンでは任意メモ欄を送信せず、時刻だけを記録する。
- 任意メモは `メモ反映` ボタンで対象日に反映する。
- 任意メモが空の場合、分類処理は行わず失敗として扱う。
- 任意メモはキーワードと正規表現によるローカルルールで分類する。
- 分類結果として届出内容、経費内容、金額、信頼度、確認要否を扱う。
- 届出内容は勤務した拠点、建物名、駅名などの場所情報として扱う。
- 経費内容は金額に対応する内容として扱い、交通費の場合は経路のみを記録する。
- 信頼度がしきい値未満、または確認要否がある場合は Excel 反映せず確認待ちとして記録する。

### 5.3 Excel 勤務表反映

- 設定ファイルで指定した Excel ファイル、シート、列定義に従って勤務表へ反映する。
- 対象日付の行を検索し、出勤時刻または退勤時刻を書き込む。
- `メモ反映` の分類結果がある場合、届出内容、経費内容、金額を書き込む。
- 金額は金額欄にのみ書き込み、届出内容・経費内容には金額表現を含めない。
- 設定された既定値があり、対象セルが空の場合は勤務表の既定項目を書き込む。
- 既存の出勤・退勤セルに値がある場合は上書きせず失敗として扱う。

### 5.4 日別表示・編集

- Slack App Home の日付選択から対象日の編集モーダルを開く。
- SQLite に記録された対象日のイベントを表示する。
- 出勤、退勤、届出内容、経費内容、金額を手動編集できる。
- 保存時は Excel 勤務表へ上書き反映し、手動編集履歴を SQLite に保存する。

### 5.5 監査ログ

- Slack受付イベントと同期状態を DynamoDB に保存する。
- Windows Agent の Excel 反映試行を SQLite に保存する。
- Excel 反映済み、反映失敗、確認待ちなどの状態を保存する。
- 手動編集の内容と結果を SQLite に保存する。
- Slack UI から変更したアプリ設定を DynamoDB に保存する。

### 5.6 時刻丸め

- v1 の既定では時刻丸めを行わない。
- 設定で 5分、10分、15分、20分、30分単位の丸めを有効化できる。
- Slack App Home から丸め単位を選択できる。
- Slack App Home で選択した丸め単位は再起動後も維持される。
- 丸め方向は nearest、floor、ceil を指定できる。
- 出勤と退勤で別の丸め方向を指定できる。

## 6. 成功の定義

- Slack App Home から出勤・退勤を記録できる。
- 設定された Excel 勤務表の対象日行へ時刻が反映される。
- 任意メモから届出内容、経費内容、金額を分類し、明確な場合は勤務表へ反映できる。
- 失敗または確認待ちのイベントが SQLite に残り、後から確認できる。
- 日付選択から対象日の勤務データを編集し、Excel へ上書きできる。
- Windows 端末停止中でも Slack 操作が DynamoDB に保存され、Windows Agent 起動後に同期される。
- リント、型チェック、単体テストを通じて主要ロジックの品質を確認できる。

## 7. ビジネス要件

- クラウド上に勤務表ファイルや Excel password を保存しない。
- クラウドには Slack 受付、丸め・分類結果、同期状態に必要な最小限の勤怠イベントだけを保存する。
- 秘密情報はリポジトリに保存せず、環境変数またはローカルの未追跡ファイルで管理する。
- 既存の Excel 勤務表フォーマットに合わせて列や行範囲を設定できる。
- Windows Agent はローカル PC 起動中のみ Excel 反映するが、Slack 受付はクラウド側で継続できる。

## 8. ユーザーストーリー

### US-001 出勤を記録する

ユーザーとして、Slack App Home の出勤ボタンを押すことで、現在時刻を Excel 勤務表へ反映したい。

### US-002 退勤を記録する

ユーザーとして、Slack App Home の退勤ボタンを押すことで、現在時刻を Excel 勤務表へ反映したい。

### US-003 メモを反映する

ユーザーとして、勤務した拠点や交通費の経路・金額などの任意メモを、出勤・退勤とは別操作で対象日に反映したい。

### US-004 曖昧なメモを確認待ちにする

ユーザーとして、分類が曖昧なメモは自動反映せず、後から確認できる状態にしたい。

### US-005 対象日を編集する

ユーザーとして、日付を選択して出勤・退勤・届出・経費情報を修正し、Excel 勤務表へ上書きしたい。

### US-006 失敗を追跡する

ユーザーとして、Excel 反映に失敗した場合でも、入力内容とエラー内容をローカルに残したい。

## 9. 受け入れ条件

- Slack App Home を開くと、任意メモ入力欄、出勤ボタン、退勤ボタン、日付選択、丸め単位選択が表示される。
- 出勤ボタンを押すと、対象日の出勤列へ時刻が書き込まれる。
- 退勤ボタンを押すと、対象日の退勤列へ時刻が書き込まれる。
- 丸め単位を選択すると、クラウド運用時は DynamoDB に保存され、以降の打刻時刻へ適用される。ローカル Bolt 運用時は SQLite に保存される。
- メモ反映で空メモの場合、分類処理は行われず失敗として保存される。
- ローカルルールで分類できない場合、確認待ちとして保存される。
- 分類結果が確認待ちの場合、Excel へ反映せず SQLite に `needs_confirmation` として保存される。
- Excel セルに既存値がある場合、打刻処理は上書きせず失敗として SQLite に保存される。
- 日付選択から編集モーダルを開き、保存すると Excel へ指定値が上書きされる。
- 手動編集結果は SQLite の手動編集履歴に保存される。
- 設定ファイルから Excel パス、シート名、列、データ行範囲、タイムゾーン、丸め設定を読み込める。

## 10. 機能要件

### Slack 連携

- HTTP Request URL 方式で Slack App と接続する。
- App Home を公開し、ユーザー操作を受け付ける。
- Interactivity によるボタン操作、日付選択、モーダル送信を処理する。

### 設定

- JSON 設定ファイルからアプリケーション設定を読み込む。
- Slack Bot Token、Slack App Token、Excel パスワードは環境変数から読み込む。
- Excel 列定義は設定で変更可能にする。

### データ保存

- SQLite に打刻イベントを保存する。
- SQLite に手動編集履歴を保存する。
- ローカル Bolt 運用では SQLite に App Home で変更した丸め単位を保存する。
- 打刻イベントは Slack イベント ID により重複更新できる。
- DynamoDB にクラウド受付イベント、丸め設定、同期状態を保存する。

### Excel

- xlwings を使ってパスワード付き Excel ファイルを開く。
- 指定シート内で対象日付に一致する行を検索する。
- 打刻時は出勤・退勤セルの既存値を保護する。
- 手動編集時は指定項目を上書きできる。

### 分類

- ローカルルールによる分類結果を扱う。

## 11. 非機能要件

### セキュリティ

- 秘密情報を Git 管理対象に含めない。
- Excel パスワードは環境変数から取得する。
- Slack Token は環境変数から取得する。
- ユーザー入力は Slack Block Kit の入力として受け取り、Excel 書き込み時に型変換する。

### 可用性

- Slack受付はAWS Lambda Function URLで行う。
- Windows Agent停止中のイベントはDynamoDBに未同期として残す。
- Windows Agent起動後に未同期イベントを条件付きclaimしてExcelへ反映する。
- 反映成功・失敗報告は、claim時に保存された `claim_token` が一致する場合だけ受け付ける。

### 保守性

- Slack UI、業務サービス、分類、Excel 書き込み、SQLite 保存をモジュール分割する。
- 設定値はコードに固定せず設定ファイルと環境変数で管理する。
- 主要な純粋ロジックと永続化ロジックは単体テストで検証する。

### 監査性

- 打刻時刻、反映時刻、状態、エラーを保存する。
- メモ反映時は分類結果、対象日、状態、エラーを保存する。
- 手動編集の内容、対象日、状態、エラーを保存する。

### 性能

- 単一ユーザーまたは小規模利用を想定する。
- Excel 操作はローカルファイルの開閉を伴うため、リアルタイム大量処理は対象外とする。

## 12. スコープ外

- 複数ユーザーの複雑な権限管理。
- Excel 以外の勤務表フォーマットへの対応。
- Web 管理画面。
- 勤怠承認ワークフロー。
